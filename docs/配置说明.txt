Mayday Airways 存档 MOD · 配置说明
==================================

配置文件位置：
    游戏根目录\BepInEx\config\com.dsh.maydaysave.cfg

修改后**重启游戏**生效。文件不存在时，启动一次游戏会自动生成。


一、总开关列表
--------------

[General]
Notify        = true    弹出提示（存读档成功/失败的小提示）
BagFreeMode   = true    读档清空全部行李 + 乘客设为「无行李」
PartialBags   = false   随机挑几位乘客保留行李需求（仅 BagFreeMode 开启时有效）
BagFallback   = true    行李不足时补发（仅 BagFreeMode 关闭时有效）


二、行李相关的三种玩法
--------------------

【方案 A｜默认】跳过行李
    BagFreeMode  = true
    PartialBags  = false
    → 读档后世界里没有任何行李，乘客也不等行李。
    → 不用搬箱子、不用交付，不会因为没行李扣钱。
    → 推荐。界面底部也会提示这一点。

【方案 B｜留一点行李玩法】
    BagFreeMode  = true
    PartialBags  = true
    → 先清空行李，再随机挑 1~N 位乘客（N ≤ 乘客总数）保留行李需求，
      行李会直接发到玩家脚边（拿不到则进背包）。
    → 需要自己把行李交给那几位乘客。

【方案 C｜完全不干预行李】
    BagFreeMode  = false
    BagFallback  = false
    → MOD 不读、不改、不删、不生成任何行李。
    → 最保守，绝不会破坏传送带；但读档后行李是"上一局遗留"的状态。


三、关闭 BagFreeMode 之后会变成什么样
----------------------------------

关掉之后 MOD 不再销毁行李，也不再改乘客的行李状态，具体表现：

1. 读档后世界里会保留**读档那一刻已有的行李**（不会清空）；
2. 如果这些行李是上一局遗留的，可能出现"看得见、拿不动"的幽灵行李
   —— 这是游戏传送带的所有权机制导致的，关掉本功能后 MOD 不再处理；
3. 乘客仍按游戏自己的逻辑等待行李：行李不够时可能超时、扣钱；
4. 传送带不会再出现"只能向外滚、不能往里收"的卡死
   （那个问题正是由销毁行李引起的，关掉本功能即可避免）。

也就是说：
    BagFreeMode = true   → 流程顺畅，但读档会清空行李
    BagFreeMode = false  → 保留行李现状，但可能有幽灵行李 / 乘客超时


四、其它开关
-----------

Notify = false    关闭所有游戏内弹窗提示（只在日志里记录）。


五、出问题怎么办
---------------

1. 先看日志：游戏根目录\BepInEx\LogOutput.log
   搜索 [save] / [load] 开头的行，能看出存读档卡在哪一步。
2. 想完全恢复原状：
   - 把 BagFreeMode 改成 false；
   - 或者直接运行根目录下的「卸载.ps1」，会把 MOD 及运行库一并移除。
3. 存档位置：游戏根目录\BepInEx\MaydaySave\saves\slot1.txt ~ slot10.txt
   这些是纯文本，可以直接备份/复制给别人。


六、已知问题（截至 v5.0.1）
-------------------------

1. 行李不能"精确按存档复原"：读档时会按上面的方案 A/B/C 处理；
2. 加油过程中存档，金额偶尔会有偏差 → 建议加完油再存；
3. 乘客情绪与个别交互状态只能还原一部分；
4. 联机时非房主的物品在极端情况下可能重复一次 → 丢掉一件即可。
